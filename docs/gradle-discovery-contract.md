# Complete bounded Gradle discovery

JVM and Kotlin analysis read each Gradle build, lock, settings, or version-catalog input with a 32 MiB limit. A sequential adapter or identity pass admits at most 256 MiB of unique input bytes. Repeated catalog captures share accounting; the budget retains counts rather than whole build files. Exact limits are accepted; a one-byte probe rejects a larger input. These internal limits are not user configuration.

A missing optional default catalog remains harmless. Explicitly configured missing catalogs, incomplete parsing, cancellation, and exhausted discovery budgets return a typed `shared.GradleDiscoveryError` with the original cause. Resource errors include the limit and observed lower bound and recommend a smaller intentional project scope. Existing semantic warnings, skipped directories, regular-file filtering, source scan limits, and POM byte policy remain unchanged. Legacy warning-only parser helpers remain available to their existing callers.

When identity preview selects any JVM or Kotlin candidate, its mixed manifest snapshot counts every non-directory entry, including unrelated files and symlinks, up to 100000. Directory errors and truncation are fatal even before the first Gradle file is discovered, on an adapter cache hit, or when the selected adapter returns no dependencies. Optional unrelated identity evidence retains its existing warning policy after a complete snapshot.

An invocation defers cache publication until all candidates, checked merge, identity enrichment, and report finalization succeed, with a cancellation check immediately before publication. Pending reports borrow immutable Maven evidence and remain separate from mutable normalized report fields. Publication uses the original cache receiver, prepared entries, and input digests. Existing read-only/off behavior and nonfatal cache-admission warnings remain. This is analysis-completion gating, not an atomic filesystem transaction across cache entries. JVM and Kotlin keys include the strict Gradle policy version, preventing reuse of older partial results.

The JVM adapter's mixed scan cannot promise completeness after a budget stops it: a later entry could be Gradle. Consequently the former public partial-success case beyond the adapter candidate cap now fails. With a complete identity snapshot, the Maven evidence provider still combines its immutable captured catalog with uncaptured POMs, preserving late identity recovery without rereading captured documents.
